# Contributing to Biomes Unseen

This document is about the pipeline, not the prose. Almost everything the game
loads is generated from `tools/content/`, so "adding a biome" means editing a
dataclass and re-running generators — not writing JSON, not writing Java, and not
drawing pixels.

---

## The one rule that explains the rest

**Author content once, in the content tables. Everything else is derived.**

A hand-listed emission set will drift from the authored content. This has already
happened three times in this repository's history:

- a pass emitting stones skipped 19 that biomes referenced
- item models were emitted only for item *textures*, missing 263 block items
- the mod's own description claimed 34 structures while 115 were being emitted

Each was fixed by deriving the set from the tables instead of listing it. When you
add a new category of thing, derive its membership by walking the content tables
or the registry — never by writing a list.

---

## Golden rules

These are invariants, not preferences. The validator enforces most of them.

1. **No procedural shape-drawing for textures.** No `draw.rect`, no `draw.ellipse`,
   no `fill`. Pixel art is authored as glyph character maps and palettes in
   `tools/pixelart/`, and every row is a literal fixed-width ASCII string.
   `engine.to_hex_matrix` can dump any texture as a literal hex matrix.

2. **No `CubeListBuilder`, no `ModelPart`.** Creatures are GeckoLib `.geo.json`
   rigs with `.animation.json` keyframes, generated by
   `tools/generate_geckolib.py`.

3. **No flat recolors.** Every texture carries a 1px dark outline, stipple
   dithering, ambient occlusion in crevices, and key light from the top left.
   The glyph vocabulary in `tools/pixelart/creature_maps.py` documents the
   tokens (`H` specular, `L` key light, `M` mid tone, `D` form shadow,
   `S` ambient occlusion, `O` outline, and so on).

4. **No missing textures.** Every egg, item, armour piece, block and mob has a
   valid PNG. The validator resolves every texture reference in JSON and in Java.

5. **No dead AI.** Every hostile and every boss carries `melee_attack`,
   `hurt_by_target` and `nearest_attackable_target_player`. The validator fails
   the build if any of the three is missing from a hostile's goal list.

6. **No placeholders that compile and do nothing.** If something is not finished,
   it is reported by the validator as a counted gap. See
   [Known gaps](#known-gaps-and-how-they-are-tracked).

## Regenerating

Run these in order. Two dependencies are load-bearing: structures reads the
template pools worldgen emits, and the validator must run last.

```bash
python3 tools/registry.py --write       # only if you changed block/item derivation
python3 tools/generate_textures.py
python3 tools/generate_resources.py
python3 tools/generate_worldgen.py
python3 tools/generate_structures.py
python3 tools/generate_geckolib.py
python3 tools/generate_java.py
python3 tools/validate.py               # must print "validation clean."
```

CI re-runs all of these and **fails if the output differs from what is
committed**. If you edit a content table, commit the regenerated files with it.

## Adding a biome

Edit `tools/content/biomes.py` and append a `BiomeSpec`. The fields that are easy
to get wrong:

- `dimension` — one of `overworld`, `hollow_deep`, `aetherfall`, `void_between`.
  This decides which biome source places it.
- `surface_top` / `surface_filler` / `surface_stone` — must resolve to a
  registered block. For Overworld biomes these become TerraBlender surface rules;
  for dimension biomes they become that dimension's `surface_rule` entries.
- `tree_feature` / `flora_feature` — the generator emits a configured and placed
  feature pair for each id it sees. Reuse an existing id to share a feature.
- `spawns` — tuples of `(entity_id, weight, min_count, max_count)`. Every entity
  id must be authored in `mobs.py`; the validator checks this.
- `structures` — must name a `StructureSpec` id. Checked in **both** directions:
  biome → structure and structure → biome. A reference in only one direction is
  an error.
- `music` / `ambient_sound` / `particle` — namespaced ids. Music and ambience are
  only emitted into the biome JSON if the `.ogg` exists, so an unshipped track
  is silently omitted rather than referenced.

**An Overworld biome needs one more thing to actually generate.** Being defined
is not the same as being placed: it must appear in
`BUContent.SEEDED_OVERWORLD_PARAMETERS`, which the TerraBlender region reads.
That table is generated from every biome whose `dimension == "overworld"`, so
nothing extra is needed — but the validator checks it explicitly, because a biome
missing from that table is registered, complete, and invisible.

Then re-run the generators and the validator.

## Adding a creature

Edit `tools/content/mobs.py` and append a `MobSpec`.

- `family` — one of `arthropod`, `avian`, `biped`, `fungal`, `quadruped`,
  `serpent`. This selects the shared rig; a new family needs a rig authored in
  `tools/generate_geckolib.py` **and** an atlas composed in
  `tools/pixelart/creature_maps.py`.
- `goals` — snake_case tokens mapped to real `Goal` instances by
  `BUGoalFactory`. An unknown token is a deliberate silent no-op so a typo cannot
  crash world load; check the factory before inventing a token.
- `animations` — the clips the species declares. Every one must exist in its
  family's `.animation.json`, and the validator enforces that. A clip named but
  not defined makes GeckoLib throw at load.
- `overlays` — keys into `creature_maps.OVERLAYS`, applied to the family atlas.

Hostiles must carry the three mandated combat goals (Golden Rule 5).

Creature atlases are 64×64. They were 64×32 until the tail band had nowhere to
live and was composed over two limb cells; see
[Atlas layout](#atlas-layout) before changing anything here.

## Adding a boss

Edit `tools/content/bosses.py`. A `BossSpec` carries a list of `BossPhase`, and
each phase names an `entry_animation`.

**Every `entry_animation` must exist in that boss's `.animation.json`.** The
generator emits a clip for each one, and `BUBoss` starts it on every phase
transition. GeckoLib throws when a controller starts an undefined clip, so a
missing one breaks the fight at the first phase change rather than degrading
quietly. The validator checks the full set: the base clips, every phase's entry
animation, and every `animation.phase.<index>` loop.

A boss also needs an arena. `arena_structure` names a `StructureSpec`, and
`tools/boss_arenas.py` holds its layout keyed by boss id. Arenas are authored
against the boss's phase mechanics — the Skyward Crown's has no walls because
`aerial_dive` is only a threat if falling off is possible — so a new boss should
get a real layout rather than falling back to the generic one.

## Adding a structure

Edit `tools/content/structures.py`. `start_jigsaw_pool` is an **unqualified** path
(`boss/<id>` or `structures/<id>`); the generator namespaces it.

`loot_tables` is a list, and every entry must end up in a chest.
`generate_structures.chests_for` raises if a table cannot be placed, because a
structure that generates without its reward is invisible in game. Each structure
should guarantee at least one lore chest.

Geometry comes from an archetype in `generate_structures.py`, selected by tokens
in the structure id, and is dressed in the materials of the biome it generates
in. Boss arenas bypass this and use `tools/boss_arenas.py`.

## Atlas layout

Creature atlases are 64×64 and are composed region-by-region in
`tools/pixelart/creature_maps._atlas()`. The composition order is the source of
truth; the module docstring documents it and `_seg()` asserts every region's
width at import time, so a mis-counted region fails loudly instead of shifting
art onto the wrong body part.

| Rows | Contents |
|---|---|
| v0–7 | head right / front / left / back (8 cols each), torso right, torso front |
| v8–15 | head top, head bottom, torso back, torso top (16 cols each) |
| v16–25 | four limb cells, 16 cols each: right \| front \| left \| back, 4 cols per face, no gutter |
| v26–29 | limb root occlusion |
| v30–33 | free |
| v34–45 | **tail**: four 3-column faces side by side |

`generate_geckolib.py` samples these regions with per-face UV rather than
Bedrock's standard box unwrap, because the atlas was laid out by hand and does
not follow that convention. Every face's `uv_size` matches its region exactly, so
nothing is stretched.

**The tail band used to overlap the limbs.** At 64×32 every row was spoken for,
so the tail was patched over the front-right and back-left limb cells — two legs
quietly repainted with tail art, and the rigs then omitted the tail bone entirely
to avoid the corruption. Growing the atlas fixed both. If you add another body
part, give it a band of its own; do not overlay an existing cell.

Which families get a tail bone is derived from the art, not hardcoded:
`tail_is_real()` asks whether the family's tail regions contain anything beyond
`.` and `O`. Biped's tail is outline-only, so it correctly gets no bone — a box of
pure outline would read as a floating wireframe.

## Validation

`tools/validate.py` is the offline equivalent of launching the game. Run it before
every commit; CI runs it and will fail the build.

A note on reading its output: it prints at most 120 errors and then a count. When
triaging, get the real total rather than eyeballing the truncated list.

### Known gaps and how they are tracked

A gap that is invisible will stay open. Two are currently tracked:

- **Overworld biome placement** — checked by `check_biome_placement`. Every
  Overworld biome must appear in the TerraBlender region's parameter table and in
  the surface-material table. Currently satisfied for all 80.
- **Audio** — checked by `check_audio`. 29 sound ids are authored with no `.ogg`,
  so music and ambience are silent. Reported as a counted note, and the rule
  enforced is that *nothing may reference audio that does not exist*.

If you leave something unfinished, add a check that reports it. That is what
turned both of the above from silent holes into tracked ones.

## CI and debugging a red build

`.github/workflows/build.yml` runs `validate` then `build`.

Actions serves job logs from blob hosts that are not always reachable, so a red
build can be unreadable through `gh run view --log`. `tools/ci_report.py` works
around this by republishing javac's `file:line: error:` lines and Gradle's *What
went wrong* block as **check-run annotations**, which are readable through
`api.github.com`:

```bash
gh api repos/<owner>/<repo>/actions/runs/<run-id>/jobs \
  --jq '.jobs[] | select(.name|test("Compile")) | .id'
gh api repos/<owner>/<repo>/check-runs/<job-id>/annotations?per_page=100
```

Two things worth knowing if you touch it:

- GitHub **silently drops file-scoped annotations** (`::error,file=X,line=N::`)
  once a run produces many of them. A 74-error build came back with only the
  summary. Diagnostics are therefore chunked into generic annotations with the
  file and line kept in the message text.
- Long messages are chunked at 900 characters across at most 24 annotations,
  because the runner truncates anything larger.

## Things that will bite you

Learned the hard way, in roughly the order they cost the most time.

**Java / Forge 1.20.1**

- `ArmorMaterial` is indexed by `ArmorItem.Type` (helmet, chestplate, leggings,
  boots), **not** by `EquipmentSlot`. Reordering the defence array silently swaps
  a helmet's defence onto the boots.
- `Tier.getIncorrectBlocksForDrops()` and `BlockTags.INCORRECT_FOR_*_TOOL` are
  1.20.5+. In 1.20.1 harvestability is `Tier.getLevel()` plus the
  `needs_*_tool` block tags.
- The entity-instance hook is `fireImmune()`. `isFireImmune()` belongs to
  `EntityType`, so overriding it on an entity overrides nothing and the authored
  immunity is silently ignored.
- `createMonsterAttributes()` is on `Monster`, not `Mob`.
- `SurfaceRules.stoneDepthCheck` takes a `CaveSurface`. Use the `ON_FLOOR` /
  `UNDER_FLOOR` constants instead.
- `Entity.portalCooldown` is private. Keep your own cooldown in the entity's Forge
  persistent data — which also stops a nether trip from suppressing your portal.
- Forge's `ITeleporter` declares `placeEntity`. Its `getPortalInfo` takes
  `Function<ServerLevel, PortalInfo>` and returns a `BlockPatternMatch`, so an
  overload taking `Function<Entity, PortalInfo>` is a name clash with the same
  erasure, not an override.
- `FlowerBlock` requires a suspicious-stew `MobEffect`. Use `BushBlock` for
  generic flora so 27 species need not each claim a vanilla effect.
- Do not override `IClientFluidTypeExtensions.getFogColor`; its signature is
  version-fragile and it pulls client classes into a common-path class.
- A bare array initialiser (`{"a","b"}`) is illegal as a method argument. It must
  be `new String[] {"a","b"}`.

**GeckoLib 4**

- There is no `software.bernie.geckolib.entity` package — that was GeckoLib 3.
  The contract is `core.animatable.GeoAnimatable`. Getting this wrong cascades:
  every `GeoModel<T>`, `GeoEntityRenderer<T>` and `AnimationController<T>` type
  argument then falls outside its bound.
- `GeoModel` is an abstract **class**, not an interface.
- `AnimationController`'s `transitionTicks` is an `int`, and the diamond in
  `new AnimationController<>(...)` cannot be inferred against an
  `AnimationPredicate` method reference — write the type argument out.

**Python / this pipeline**

- Global `str.replace` is unsafe for identifier rewrites; it has clobbered
  unrelated functions. Scope rewrites by function using a line-range helper.
- Line-scoped slice replacement can delete a function header. Always
  `grep -n '^def '` after a slice edit. And check that your end anchor actually
  follows your start anchor — a slice with `end < start` silently duplicates
  content, and Python's later definition wins without complaint.
- Wrap every patch in `assert old in source`. Anchors that silently do not match
  are how a "fixed" file stays broken.
- Do not pipe generator output through a filter when verifying a change; it hides
  crashes.
- `Writer.json()` does not append `.json`. Audit with
  `find src/main/resources/data -type f ! -name '*.json'`.
- A glob one level too shallow reports a false negative. This produced
  "0 missing structure NBT" while all 115 were missing, because the template
  pools are nested a directory deeper than the pattern assumed.
